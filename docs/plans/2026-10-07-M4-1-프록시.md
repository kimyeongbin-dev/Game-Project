# M4-1 — 리버스 프록시(Caddy) · 신뢰 경계 · 오리진 · IP 접속 리밋 · 프록시 경유 E2E

## Context

ROADMAP M4 "리버스 프록시 + E2E 서비스 흐름 검증"의 첫 계획. 목적은 **상용에서만 드러나는 버그를 로컬에서 재현**하는 것이다.
지금은 클라이언트가 uvicorn 에 직접 붙고, 서버는 prod·하네스 모두 `--forwarded-allow-ips *` 다. 서버 포트에 닿는 누구든
`X-Forwarded-For` 를 위조해 레이트 리밋 키를 바꿀 수 있고(전원 공유 또는 우회), 프록시를 두면 반대로 모든 사용자가 프록시 IP 하나를
공유한다. CORS 는 `*`(TODO "프로덕션 배포 전 필수"), WS 접속 리밋은 유저 단위뿐이라 무효 토큰 연타(검토 #1 R11 나머지)를 못 막는다.

**사용자 결정 (2026-10-07, 이 계획 수립 중):**
1. **TLS 는 플랫폼 엣지에서 끝낸다.** Caddy 는 컨테이너 안에서 HTTP 로 받는다 — 로컬·CI·배포가 **같은 Caddyfile**, 인증서 차이 없음
2. **공식 Caddy 이미지 승인** — `caddy:<2.x>-alpine@sha256:…` 다이제스트 고정, 플러그인 빌드 없음
3. **M4 를 둘로 나눈다.** 이 계획(M4-1) = 프록시·신뢰 경계·CORS/WS Origin·IP 접속 리밋·프록시 경유 E2E. **M4-2** = 수신자별 전송 큐·
   재동기화 루프 밖 이동·이벤트당 왕복(검토 #1 R8·#2 Q12)·부하(워커 3+, 수백 게임) — 비용 추정·파일럿 먼저, 별도 계획
4. **배포처 중립.** 신뢰 대역은 환경변수로만 받는다. 로컬·CI 는 compose 네트워크의 고정 주소. Fly/ECS 값은 배포 작업 때

**진행 규칙:** 커밋마다 검증 관문 G1~G5(plans/README). 마지막에 독립 검토 1회(코드·하네스·설계서 전부) + 채택표.

## 판단

### 1. 신뢰 경계 — 두 단, 각자 바로 앞만 믿는다

```
클라이언트 ─(엣지: Fly/ALB, 배포만)─> Caddy :8080 ──> uvicorn server:8000
            Caddy: CADDY_TRUSTED_PROXIES 만 믿는다     uvicorn: FORWARDED_ALLOW_IPS = Caddy 주소만 믿는다
```

- **Caddy** — `servers { trusted_proxies static {$CADDY_TRUSTED_PROXIES} }`. 로컬·CI 는 비움 → 들어온 XFF 를 버리고 접속 주소를
  클라이언트로 본다. 배포는 엣지 대역(배포 작업 때). `reverse_proxy` 가 XFF 를 다시 쓴다(신뢰 안 된 값은 덮어쓴다)
- **uvicorn** — CMD 에서 `--forwarded-allow-ips *` 를 **뺀다**(`--proxy-headers` 는 유지). 값은 `FORWARDED_ALLOW_IPS` 환경변수 —
  compose 는 Caddy 의 고정 주소. 미설정이면 uvicorn 기본 `127.0.0.1`(fail-closed: 아무 XFF 도 믿지 않는다). 이 변수는 앱이 아니라
  uvicorn 이 읽는다 — `config.py` 단일 진입점 원칙의 예외로 Dockerfile 주석·CLAUDE.md 에 명시
- **server 포트를 호스트에 열지 않는다.** 호스트 `${SERVER_PORT:-8000}` 은 Caddy 로. 클라이언트 API Base URL(10.0.2.2:8000 등)은 그대로
- compose 네트워크에 고정 서브넷(`GAMEMOA_SUBNET`, 기본 `172.30.0.0/24`) + Caddy `ipv4_address` 고정. 같은 네트워크의 다른 컨테이너는
  XFF 를 믿게 만들 수 없다(Caddy 주소만 신뢰)

### 2. Caddyfile — `infra/caddy/Caddyfile` 하나

- `:8080` 에서 `reverse_proxy server:8000`. WS 업그레이드는 Caddy 기본 지원(업그레이드 뒤 바이트 터널 — ping/pong·close 코드 1012·4000 이
  그대로 지난다). `flush_interval -1`
- **접속 로그를 남기지 않는다**(사이트 `log` 없음) — 켜면 URI 의 `?token=` 이 Caddy 로그로 샌다(maze.md §2 원칙). 켤 때는
  `format filter` 로 `request>uri` 쿼리 삭제가 필수라고 Caddyfile 주석에. 가드 테스트가 `log` 지시어 없음을 검사
- `admin off`, `auto_https off`(엣지가 TLS), 헬스 `/health` 는 프록시 경유로도 열린다
- 업스트림 이름(`server:8000`)은 `{$CADDY_UPSTREAM:server:8000}` — 배포처에서 바꿀 수 있게

### 3. CORS · WS Origin

- `config.py`: `cors_allowed_origins: list[str]`(개발 기본 `["*"]`), **production 에서 `*` 가 있으면 기동 거부**(validator — 빈 목록 =
  브라우저 오리진 없음, 네이티브 앱은 Origin 을 보내지 않는다). `allow_credentials=False`(인증은 bearer, 쿠키 없음 — `*` + credentials 조합 제거)
- WS: 핸드셰이크에 `Origin` 이 **있으면** 허용 목록과 대조, 없으면 통과(네이티브 앱). 불일치 → accept 전 거절(HTTP 403 — 브라우저는 어차피
  close 코드를 못 읽고, 토큰 검증 전에 끊는다). `*` 면 대조 없음(개발)

### 4. IP 접속 리밋 (검토 #1 R11 나머지)

- `ConnectLimiter` 에 IP 창 추가 — 키 `ws:{ns}:connect-ip:{ip}`(리미터 DB, `redis_keys.ws_connect_ip_rate`), `ws_connect_per_minute_ip`
  기본 120(모바일 통신사 NAT 공유 대비 유저 리밋 20 의 6배). **토큰 검증 전**에 — 무효 토큰 연타가 서명 검증·로그를 태우지 못하게
- 초과 → accept 후 close 1013(유저 리밋과 같은 코드). IP 는 `websocket.client.host`(판단 1 이 교정한 값). 리미터 장애는 fail-open(기존과 같다)

### 5. 프록시 경유 E2E — 하네스 확장 + 경량 E2E 테스트

- **하네스**(`server/harness/multiworker/`): `proxy` 서비스(같은 Caddyfile·같은 이미지) 추가, 클라이언트 기본 대상을 프록시로
  (`HARNESS_TARGET=proxy|direct`). M3 시나리오 S1~S9 를 **프록시 경유로** 다시 + 새 시나리오 P1~P6(아래)
- **경량 E2E**(`server/e2e/`, pytest, 기본 스킵 — `E2E_BASE_URL` 이 있을 때만): compose 로 `proxy`+`server` 를 띄우고 `server-test`
  컨테이너에서 프록시로 — 헬스, WS 업그레이드·인증 거절 코드, XFF 위조 무시, CORS 프리플라이트, Origin 거절. **로컬과 CI 가 같은 명령**
- CI `test-and-merge.yml` 에 `proxy-e2e` 잡(기존 액션 SHA 재사용, 새 액션 없음)

## MUST / MUST NOT

- MUST: 서버는 Caddy 주소만 신뢰 / 토큰이 어떤 로그에도 남지 않음 / production CORS fail-closed / IP 리밋은 토큰 검증 전 / Caddy 이미지
  다이제스트 고정 / 액션은 기존 SHA 재사용 / 환경변수는 `config.py`(uvicorn 이 읽는 `FORWARDED_ALLOW_IPS` 만 예외로 명시) / 키는 `redis_keys.py`

  M4-2 항목(전송 큐·재동기화·부하) 착수 / 2.5단계 재개
