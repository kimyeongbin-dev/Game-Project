**1. CPU 상한 4** (사용자 결정)

- `docs/_private/m2_5_selfplay/compose.yml` 에 `cpus: 4` — **반영됨**
- `selfplay.py` 의 `Pool(os.cpu_count())` → 워커 4 (`SELFPLAY_WORKERS`, 기본 4). `cpus:` 는 CPU 시간 할당량이라 컨테이너 안의 `os.cpu_count()` 는 그대로 8 을 돌려줄 수 있다(추정 — 재개 시 확인) [상위]

**2. 세션 제한을 넘는 실행**

- **분리 실행:** `$C run -d selfplay python selfplay.py <실험>` — 컨테이너가 Claude 세션·에이전트와 무관하게 산다. `--rm` 은 쓰지 않는다(종료 후 로그 보존), 끝나면 `$C down --rmi local`
- **하네스는 상위 세션이 직접 띄운다.** 서브에이전트가 띄우면 에이전트 중지·제한 시간이 실행을 죽인다
- **대기:** 결과 파일 기준 `until` 루프를 Monitor/백그라운드로 건다(최대 2시간, 만료 시 재무장). 컨테이너 종료·`Traceback` 도 같은 필터로 잡는다

**3. 묶음을 잘게 — 결과를 단계적으로 본다** (사용자 요청)

- **청크 = 250판.** 청크마다 `results/<실험>/chunk_<k>.json` 을 쓰고, 이미 있는 청크는 건너뛴다 → 중단돼도 끝난 청크는 남고 이어서 돌릴 수 있다. `aggregate` 서브커맨드가 청크를 합산한다 [상위]
- **1차 표본: 실험당 500판(청크 2개).** 1차 결과를 사용자에게 보고하고, **확대 여부는 사용자가 정한다.**
  근거 — 승률 50% 부근 95% Wilson 구간 반폭:

  | 표본 | 반폭 |
  | :-- | :-- |
  | 500판 | ±4.4%p |
  | 1,000판 | ±3.1%p |
  | 2,000판 | ±2.2%p |

  편향이 크면 500판으로 결론이 나고, 50% 근처의 작은 편향을 가리려면 확대한다
- **순서:** `duel_normal` → `trio_normal` → `duel_hard`. 공평성 질문의 핵심인 trio 를 두 번째로 당긴다. 대조군(`_ctl`)은 1차 결과에서 필요가 보일 때만 돌린다

**4. 실행 시간 추정 — 본 실행 전 파일럿**

- 실험별 20판을 CPU 4 로 시간 측정(`selfplay.py time <실험> 20`) → `판당 초 × 표본 ÷ 4` 로 추정해 **사용자에게 먼저 제시**, 승인 후 본 실행
- 판정 기준: **청크 하나 ≤ 15분, 1차 전체 ≤ 1시간.** 넘으면 표본·실험 구성을 사용자와 다시 정한다
- 지금 아는 값: 최적화 전, 8 워커로 2,000판이 33분 안에 끝나지 않았다 → 판당 **약 8 스레드·초 이상**(하한 추정). 최적화판(후보 분류 캐시·BFS 생략)의 속도는 측정 전이다

**5. 하네스 검토 [상위]** — 재개 첫 작업

- `verify`(최적화 전후 결정 동일성)부터 돌린다. 하위 클래스·캐시가 AI 행동을 바꾸지 않는지, 시야 근사(§6 문구 해석) 주석이 타당한지 본다
- 위치는 그때 다시 정한다 — 보고서 수치의 재현 근거가 되려면 커밋된 위치(`server/spikes/`)가 필요하다

**하네스 검토 때 먼저 볼 것:** `SimpleAI._random_action` 은 랜덤 벽을 `valid_walls[:20]`
(스캔 순서상 앞쪽)에서만 고른다 — **코드로 확인함** (`server/app/games/maze/ai/simple_ai.py:225`).
이 편향이 좌석 승률 실측을 얼마나 오염시키는지는 **측정 전**이다. 1차 결과를 해석할 때
대조군을 돌릴지 판단하는 근거가 된다.
