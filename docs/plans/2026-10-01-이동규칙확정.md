# maze.md 잔여 설계 3건 확정 — 점프 제거·말 중첩 허용으로 이동 규칙 신설

---

## Context

`docs/ROADMAP.md` "maze.md 잔여 설계 3건"이 M3(WebSocket 상태 Redis 이전 +
1:1:1 확장)의 **선행 조건**으로 걸려 있다. 2026-10-01에 미결 15건을 확정했으나
(커밋 `e8af2d6`), 그 직후 점검에서 **미결 표에 오른 적이 없어 확정 절차를 거치지
못한** 구멍 2개가 드러났다.

핵심은 ①이다. `maze.md` §5 "이동"은 payload 스키마 3줄(`row`, `col`)이 전부이고
**"어느 칸으로 갈 수 있는가"가 설계서 어디에도 없다.** §13에 `invalid_move |
이동 규칙 위반` 코드만 있고 그 "규칙"의 본문이 없다. §7이 벽 설치 검증을 4단계로
명시한 것과 비대칭이다. 그 상태로 M3에 착수하면 `core/move_validator.py` 에서
막힌다.

**결론: 쿼리도에서 물려받은 점프 규칙을 제거하고, 말이 같은 칸에 겹칠 수 있게
한다.** 시야 규칙(3×3 + 내부 변 12개 + 벽 차폐)은 **그대로 둔다.**

이 세션은 **문서만** 확정한다. 코드는 M3 작업 3(엔진 N인 일반화)에서 한꺼번에
손댄다 — 지금 `move_validator.py`만 고치면 `Player.goals[]`·좌석 목록이 없어
2인 전제에 다시 묶인다.

## 왜 점프를 제거하는가

### 1. 점프는 Fog of War와 구조적으로 충돌한다

점프를 두면 **클라이언트가 자기 합법 수를 계산할 수 없다.** 직선 점프 가능
여부는 ① 상대 **뒤쪽 변**에 벽이 있는지와 ② 직선 **착지점**에 세 번째 말이
있는지로 결정되는데, §6이 그 둘을 모두 가린다:

| 모르는 것 | 왜 |
| :--- | :--- |
| 상대 뒤쪽 변 | 3×3의 **외곽 변**이고 §6이 "어떤 경우에도 전송하지 않는다"고 못박았다 |
| 직선 착지점 | 2칸 거리로 3×3 **밖**이다 |

> **ROADMAP ①의 전제는 틀렸다.** "상대가 내 시야 밖이면…"이라고 적었지만, §6
> 직교 차폐가 안 보이게 하는 조건(두 칸 사이의 벽)과 이동이 막히는 조건이
> **같다.** 점프가 성립할 수 있는 상황에서 상대는 **반드시 보인다.** 구멍은
> 상대가 아니라 **착지 구역**이었다. 이 교정은 산출물 6에 반영한다.

이를 메우려면 서버가 착지 후보를 알려주거나(§7 "유효 수 목록을 서버가 주지
않는다"와 `platform.md` §6 `valid-moves` 폐기 근거에 **예외**를 내야 한다)
3×3 외곽 변 규칙에 **예외**를 내야 한다. **점프를 없애면 예외가 하나도
필요 없다.**

### 2. 점프는 SSOT에 없다

`PLATFORM_ARCHITECTURE.md` §4.1을 전수 확인했다. 행동은 **"이동 및 벽 설치"**
둘뿐이고, 점프도 말 충돌 규칙도 **언급이 없다**. 전 저장소 `.md` 에서 `점프`는
`docs/quoridor/game_rules.md`(폐기 대기 구 문서)와 §11 근거 문장 1곳에만 있다.
제거가 SSOT를 거스르지 않는다. 오히려 §4.1의 **"`Quoridor` 상표권 배제 및
Trade Dress 완전 해소"** 목표에 유리하다.

### 3. "몸으로 길막기"는 이 게임에서 성립하지 않는다

점프 규칙의 존재 이유는 폰 충돌이고, 폰 충돌의 전략적 의미는 "상대 길을
몸으로 막기"다. **상대가 어디 있는지 모르는 게임에서는 막을 대상을 특정할 수
없다.** 잃는 전술이 애초에 작동하지 않는다.

### 4. 조사 — 변(edge) 가시성에 정착된 best practice는 없고, 관례는 "차폐물을 더 공개"다

| 출처 | 내용 |
| :--- | :--- |
| [Red Blob Games — Thin wall FOV](https://www.redblobgames.com/x/2128-thin-wall-fov/) | **변 기반 FOV 전용 글이 미완성으로 중단**됐다 (`TODO: this is trickier`, *"was taking too much of my time"*). 칸 기반은 표준이 여럿이지만 **변 기반은 참조할 표준 구현이 없다** |
| [Albert Ford — Symmetric Shadowcasting](https://www.albertford.com/shadowcasting/) | 공개 조건이 `if is_wall(tile) or is_symmetric(row, tile)` — 바닥 칸은 중심점이 시야 섹터에 들어와야 하지만 **벽은 만나는 즉시 공개**한다. 관례는 **"열린 칸보다 차폐물을 더 많이 공개"** 다 |
| [Simon — Improving Symmetric Shadowcasting](https://scambier.xyz/blog/Improving-Symmetric-Shadowcasting-for-Tile-Bitmasking) | 벽을 일찍 공개해 생기는 아티팩트는 **데이터를 숨겨서가 아니라 클라이언트 비트마스킹을 "확인된 타일에만" 적용해** 고친다 |
| [Fog of War 체스 (chess.com 공식 변형)](https://www.chess.com/terms/fog-of-war-chess) | *"players can see only the squares where their pieces can legally move"* — **합법 수 집합이 곧 시야**다. 턴제 추상 게임에서 합법 수 공개는 금기가 아니다 |

→ 우리의 "3×3 외곽 변 비전송"은 관례의 **반대 방향**이다. 하지만 점프를
제거하면 **그 숨긴 정보가 판정에 전혀 필요하지 않게 되므로** 규칙을 완화하지
않고 그대로 유지할 수 있다. 변 기반 FOV에 표준이 없다는 점에서, **판정에
필요한 정보가 시야 규칙 안에서 자족하도록 규칙을 맞추는 것**이 더 안전하다.

### 5. 부수 효과 — 잠재 교착 2건이 닫힌다

| 닫히는 구멍 | 설명 |
| :--- | :--- |
| **이동 불가 상태** | 구 규칙에서는 3인전에서 두 면이 벽, 두 면이 상대 말이고 점프·대각이 모두 막히면 **합법 수가 0개**가 될 수 있었고 설계서에 처리 규칙이 없었다. 말이 장애물이 아니게 되면 §7의 경로 보장이 "목표까지 경로가 있다"를 보장하므로 **생존 플레이어는 항상 최소 1칸 이동할 수 있다** |
| **§7 벽 설치 잠금의 전제** | §7은 거절 3회째에 "반드시 말을 이동해야 한다"고 적었다. 이는 **이동 가능한 칸이 항상 존재한다**는 전제인데 구 규칙에서는 증명되지 않았다. 위 성질로 전제가 성립한다 |
| **`pathfinder.py` 정합** | 현행 `find_shortest_path`의 `other_player_pos`는 주석에 **"점프 계산 무시, 단순 경로용"** 으로 적혀 있다 — 말을 통과 가능으로 보고 계산한다. 말이 장애물이 아니게 되면 **현행 구현이 그대로 정확해진다.** 인자 자체가 불필요해진다 |

## 확정된 설계 결정

| 쟁점 | 결정 |
| :--- | :--- |
| **점프** | **제거.** 쿼리도에서 물려받은 직선 점프·대각 우회 규칙을 모두 없앤다 |
| **말 충돌** | **없다.** 여러 말이 **같은 칸에 겹칠 수 있다.** 인원 상한은 모드 정원이며 별도 제한을 두지 않는다 |
| **시야** | **변경 없음.** 3×3 + 내부 변 12개 + 벽 차폐 + 외곽 변 비전송 — §6을 **고치지 않는다** |
| **탈락자의 말** | **장애물이 아니다.** 살아있는 말과 동일하게 통과·중첩 가능 (§9 문구 교정 필요) |
| **작업 범위** | **문서 확정만.** 코드는 M3 |

### 유도되는 세부 — 추가 판단 없이 따라오는 것들

1. **합법 이동 = 직교 인접 1칸 + 보드 안 + 두 칸 사이에 벽 없음.** 끝이다.
   말의 위치는 이동 제약에 **전혀 관여하지 않는다.**
2. **클라이언트가 합법 이동을 100% 스스로 계산할 수 있다.** 판정에 필요한 변은
   내 4면뿐이고, §6이 *"P 는 항상 보이므로 내 4면은 언제나 전송된다"* 를 이미
   보장한다. → `jump_targets` 같은 신규 필드가 **필요 없다.**
3. **정상 플레이에서 `invalid_move`는 발생할 수 없다** — 버그·조작 시에만.
   따라서 §7식 시도 횟수 제한을 이동에 걸 이유가 없다.
4. **대각 이동은 존재하지 않는다.** 대각은 점프 우회로만 발생했으므로 함께 사라진다.
5. **`move` payload는 그대로다** (`{row, col}`). 신규 메시지 타입·에러 코드 **0건**,
   §12 집계 **불변**.
6. **목표 칸에 다른 말이 있어도 들어가 승리한다.** 목표 봉쇄가 불가능해진다.
7. **같은 칸 조우에 특별 효과는 없다.** 전투·밀어내기 같은 상호작용을 넣지 않는다.
8. **`visible_players`·`last_seen_players`에 같은 좌표가 복수 등장할 수 있다.**
   배열 스키마는 그대로 수용하지만 클라이언트가 좌석당 1칸으로 가정하지 않도록
   명기한다.
9. **패스는 없다.** 매 턴 이동 또는 벽 설치 중 하나를 반드시 한다 (현행과 동일).
10. **2인·3인 규칙이 완전히 같아진다.** 모드 분기가 이동 규칙에서 사라진다.

### 5. 미결 사항 요약 정정 (ROADMAP ③)

ROADMAP ③은 "말미의 **현재 미결 없음.** 을 ①②로 교체한다"고 적었으나, 커밋
`1502469`이 이미 경고 블록으로 교체해 둔 상태다 — **ROADMAP 기술이 한 발
뒤처져 있다.** 실제 작업:

1. `⚠️ 단, 미결 표에 오른 적이 없는 구멍 2건이 남아 있다…` 경고 블록 **제거**
2. `### 확정된 항목` 표에 **3행 추가**

   | 항목 | 결정 | 절 |
   | :--- | :--- | :--- |
   | 점프 규칙 | **제거.** Fog of War 와 구조적으로 충돌하고 SSOT 에 없다 | §5 |
   | 말 충돌 | **없다.** 같은 칸에 **중첩 허용**. 탈락자의 말도 장애물이 아니다 | §5·§9 |
   | 합법 수 계산 | **클라이언트가 자족한다.** 내 4면만으로 결정되며 서버는 목록을 주지 않는다 | §5·§7 |

3. `### 구현 선행 조건 (M3)` 표에 1행:
   `이동 규칙 | 점프 + 단일 opponent 전제 | 점프 삭제 · opponent 인자 제거 (§5)`
4. 문서 머리글 `**상태:** 설계 확정 전` → **`설계 확정`** (M3 의존 문장은 유지)
