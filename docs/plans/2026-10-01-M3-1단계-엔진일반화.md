**남기는 것 — `ws_game` 이 import 하는 4메서드만 가진 과도기 shim:**

```python
class QuoridorService:
    _games: dict[str, GameState]           # 프로세스 메모리 — 3단계에서 Redis 로 대체
    async def create_game(self, mode: str) -> GameState
    async def get_game(self, game_id) -> GameState | None
    async def move_pawn(self, game_id, row, col) -> tuple[bool, str | None, GameState | None]
    async def place_wall(self, game_id, row, col, orientation) -> tuple[...]
```

- 이름·싱글톤·`async` 는 유지한다 → `ws_game` import 와 `patch("app.ws.ws_game.quoridor_service")` 가 그대로 산다
- **`ws_game` 본문은 고치지 않는다.** 이미 어긋난 호출(위 사실 2)이고 3·4단계 재설계 대상이다. 라우터 미등록이라 실행 경로가 없다. 대신 `app/ws/__init__.py` 판정표에 "1단계 이후 `create_game` 호출부·2인 전제 필드(`current_turn`, `winner`, `player{n}_win`) 불일치" 한 줄을 남긴다
- shim 은 테스트하지 않는다 — 3단계에서 통째로 교체되는 4줄짜리 위임이다. 엔진 테스트가 실체를 덮는다

## 판단 4 — 엔진·DB 모델 불일치 구간 (2단계까지)

**서비스가 DB 를 전혀 쓰지 않게 해서 불일치 구간 자체를 없앤다.** `_save_to_db`/
`_load_from_db` 를 위 삭제에 포함한다.

- 근거: 0단계 결론으로 진행 중 상태의 권위는 Redis 다. **행동마다 DB 에 상태를 쓰는
  경로는 어차피 폐기 대상**이고, DB 는 2단계 `game_participants` 로 종료 결과만 받는다
- 결과: `GameSession`·`GameSessionRepository`·`test_repository.py` 는 1단계 동안 **앱
  코드에서 고립된 채** 그대로 남고, 2단계가 함께 다시 쓴다. 새 `to_dict()` 가 구
  `player1_name`/`current_turn` 컬럼을 채울 필요가 없다
- 대가: 1단계 동안 게임은 메모리 전용 — 노출된 경로(REST 삭제, WS 미등록)가 없으므로 손실 없음
- 구 형식 데이터 방어: `from_dict` 는 `schema_version` 이 다르면 `ValueError`. 구 `"finished"` 하위 호환 분기는 삭제

## 판단 2 — `to_dict()` 형태 (= Redis `game:<id>:state` 값)

**원칙**

1. **`to_dict()` 결과가 `game:<id>:state` 의 값 전체다.** 봉투로 감싸지 않는다
2. **규칙 상태만 담는다.** 시계(§8)·발견 맵(§6)·좌석↔유저 매핑은 갱신 트리거가 달라
   **별도 키**로 두고 같은 게임별 락 아래에서 쓴다 (3·5·6단계가 정한다)
3. **파생값을 넣지 않는다** — 최단 거리, 합법 수, `eliminated` 불리언, 잠금 여부.
   같은 사실을 두 필드가 말하면 언젠가 어긋난다
4. **배치 테이블이 바뀌어도 진행 중 게임이 살아남는다** — 좌석별 `goals`·`walls_remaining`
   을 테이블에서 재계산하지 않고 저장한다. trio 꼭짓점이 랜덤이라 어차피 저장해야 한다
5. **열거형 대신 문자열, 좌석은 키가 아닌 목록** (platform.md §5). `seat_no` 오름차순
6. 이름·닉네임을 **담지 않는다** — 정체성은 참가자 기록(2·3단계)의 몫. 엔진은 좌석만 안다

```json
{
  "schema_version": 1,
  "game_id": "8f14e45f-…",
  "mode": "trio",
  "status": "in_progress",
  "end_reason": null,
  "winner_seat_no": null,
  "current_seat_no": 2,
  "turn_count": 13,
  "wall_rejections": 1,
  "seats": [
    { "seat_no": 1,
      "position": { "row": 0, "col": 0 },
      "goals": [ { "axis": "row", "value": 8 }, { "axis": "col", "value": 8 } ],
      "walls_remaining": 6,
      "turns_taken": 5,
      "eliminated_order": null,
      "elimination_reason": null }
  ],
  "walls": [ { "row": 3, "col": 5, "orientation": "horizontal" } ],
  "created_at": "2026-10-01T09:00:00Z",
  "updated_at": "2026-10-01T09:04:12Z"
}
```

| 필드 | 이유 |
| :--- | :--- |
| `schema_version` | 이어받기 배포 중 구·신 워커가 같은 키를 읽는다. 형태가 바뀌면 판별이 필요하다 |
| `status` | `in_progress` \| `finished`. 구 `PLAYER1_WIN`/`ABANDONED` 폐기 |
| `end_reason` | `goal_reached` \| `last_standing`. `server_fault` 는 **상태를 잃었을 때**라 엔진 상태에 존재할 수 없다 |
| `wall_rejections` | §7 턴당 거절 카운터. 턴 전환 시 0. **잠김 = `>= 3`** (저장하지 않는다) |
| `turns_taken` | §9 순위 2차 기준 "사용한 턴 수". 지금 넣지 않으면 3단계 이후 스키마가 또 바뀐다 |
| `eliminated_order`/`elimination_reason` | §9 탈락 순번·사유. 둘 다 null 이면 생존 |

## 판단 3 — 엔진 일반화 순서와 테스트 전략

### 엔진 API (확정)

- **배치 테이블** `core/layouts.py` (신규) — 모드 → `Layout(slots, seats, walls_per_seat, shuffle)`.
  `slots` 는 `(start, goals)` 데이터. 선택은 `rng.sample(slots, seats)` if `shuffle` else `slots[:seats]` — **모드 무관 코드 한 줄**
  - `duel`: `(8,4)→row 0`, `(0,4)→row 8`, 10벽, 순서 고정 (구 player1/2 와 동일 배치)
  - `trio`: 네 꼭짓점 → 대각 반대 두 변, 7벽, shuffle
  - **`quad` 는 넣지 않는다** — 인당 벽 수가 미정(§11 "—"). 테스트가 임시 행으로 주입한다
- `board.py`: `PLAYER*_START`/`*_GOAL_ROW` 삭제, `Goal(axis, value).is_reached(pos)` 추가
- **행동은 좌석을 명시하고 §13 코드로 거절한다:** `move(seat_no, row, col)`,
  `place_wall(seat_no, row, col, orientation)`, `eliminate(seat_no, reason)` →
  성공 시 `None`, 실패 시 `Rejection`(값이 §13 코드인 `str` Enum). `not_your_turn` 을
  엔진이 판정한다 — 호출부가 턴 검사를 빠뜨려도 뚫리지 않는다
- **벽 검증 순서** (§7 + 사용자 결정):

  | 순서 | 조건 | 코드 | 카운트 |
  | :--- | :--- | :--- | :--- |
  | 0 | 종료된 게임 | `game_already_ended` | — |
  | 1 | 내 차례 아님 | `not_your_turn` | — |
  | 2 | 남은 벽 없음 | `no_walls_remaining` | — |
  | 3 | 이미 잠김 (`wall_rejections >= 3`) | `probe_limit_exceeded` | — |
  | 4 | 좌표 0-7 밖 / 방향값 무효 | `invalid_wall_position` | **안 센다** (정보 누출 없음) |
  | 5 | 기존 벽과 겹침·교차 | `invalid_wall_position` | **센다** |
  | 6 | 생존자 중 누군가 경로 없음 | `wall_blocks_path` | **센다** (같은 카운터) |

  3회째 거절은 원래 코드를 반환하며 잠근다. 이후 시도가 `probe_limit_exceeded`
- **탈락** `eliminate`: 순번 = 현재 탈락자 수 + 1 → 생존자 1명이면 `last_standing` 종료,
  아니고 현재 차례였으면 다음 생존자로. 사유는 `surrender`·`time_forfeit`·`disconnect_forfeit` 만 허용
- **턴 순환**: `seat_no` 오름차순, 탈락자 건너뜀. 턴 전환 시 `wall_rejections = 0`
- **순위** `standings()`: §9 그대로 — 도달자 > 생존자(남은 거리↑, `turns_taken`↑) > 탈락자(순번 역순).
  공동 순위는 경쟁 순위(1,2,2,4)
- `GameMode`(`vs_ai`/`local_2p`) 열거형 삭제 — `mode` 는 배치 테이블 키 문자열.
  엔진 `ActionType`/`Action` 은 유지 (AI 사용, platform.md §6)
- `GameState(mode, *, game_id=None, rng=None)` — `rng` 주입으로 trio 배치를 테스트에서 고정
- `utcnow` 는 `app.core.time` 에서 import, 로컬 정의 삭제

**기존 8파일은 새 API 로 옮긴다.** 의미가 사라진 것은 지운다: `TestJumpMoves`
(`test_move_validator.py`), `TestJumpScenarios`(`test_scenarios.py`), `test_game_state.py:147`
점프 회피 주석, 이름 관련 테스트(`test_create_game_with_custom_names`), `local_2p`/`vs_ai` 모드 테스트.

**신규 `tests/games/maze/test_seat_scaling.py` — 완료 판정 그 자체.**

`conftest.py` 에 `seat_mode` 파라미터 픽스처: `duel`(2) · `trio`(3) · `quad`(4).
`quad` 는 `monkeypatch.setitem(LAYOUTS, "quad", Layout(네 꼭짓점, seats=4, walls=5, shuffle=True))`
**한 줄로만 주입한다.** 아래가 4좌석에서 통과하면 "행 추가 외 변경 없음"이 증명된다.

| 테스트 | 검증 |
| :--- | :--- |
| 초기 배치 | 좌석 1..N, 시작점 서로 다름, 각 좌석 goals ≥ 1, 시작점이 자기 목표 아님, 초기 거리 8 |
| 순환 | N회 행동 후 좌석 1 복귀, 각 `turns_taken == 1` |
| 탈락 순환 | 중간 좌석 탈락 → 건너뜀. 현재 좌석 탈락 → 즉시 다음 생존자 |
| `last_standing` | N−1 명 탈락 → 종료·승자 = 생존자. N=2 는 1명 탈락으로 성립 |
| 경로 검증 = 생존자만 | 탈락자를 가두는 벽은 허용, 생존자를 가두는 벽은 `wall_blocks_path` |
| 목표 도달 | 각 좌석이 자기 goals 중 하나로 도달 → `goal_reached`. 꼭짓점 좌석은 `col` 목표로도 |
| 말 중첩 | 다른 말이 선 칸·목표 칸으로 이동 가능 |
| 거절 카운터 | 겹침 1 + 막힘 1 → 3회째 거절 후 `probe_limit_exceeded`. 범위 밖 좌표는 세지 않음. 다음 턴 리셋 |
| 순위 | 도달·생존(거리/턴 동률 → 공동)·탈락 역순 |
| 직렬화 | 중반(탈락자·벽·카운터 포함) `from_json(to_json(s)).to_dict() == s.to_dict()`. `schema_version` 불일치 → `ValueError` |
| AI 자가대전 | 시드 고정, N좌석 전원 `SimpleAI` 로 400턴 안에 종료, 예외 없음 |
| **하드코딩 스캔** | `app/games/maze/**/*.py` 에 `player[12]`, `PLAYER[12]`, `opponent_player`, `goal_row` 가 없다 — 회귀 방지 |
