# 계획서 보관소

플랜 모드로 세운 계획서를 여기 보관한다. **기록**이지 현재 상태가 아니다.

---

## 왜 저장소 안에 두는가

플랜 모드는 기본적으로 계획서를 `~/.claude/plans/`(저장소 밖)에 만든다. 그
자리에 두면 **새 세션이 존재를 모른다** — 컨텍스트를 비우면 계획이 왜 그렇게
세워졌는지, 무엇을 의도적으로 제외했는지 추적할 수 없다.

커밋 메시지에도 근거가 남지만, 계획서에는 커밋에 없는 것이 있다:

- 각 산출물의 **MUST / MUST NOT** 와 **수락 기준 체크리스트**
- **모델 분할 지침** (설계 판단이 필요한 트랙 A vs 기계적 작업 트랙 B)
- 조사로 확인한 사실과 그 근거 위치
- 범위에서 **의도적으로 제외한** 것

같은 틀로 다음 계획을 세울 때 그대로 재사용한다.

---

## 규약

### 생성 위치 — 클론당 1회 설정 (필수)

손으로 옮기는 규약에만 의존하면 잊는다. **생성 위치 자체를 저장소 안으로
돌린다.** `.claude/settings.local.json`:

```json
{ "plansDirectory": "docs/plans" }
```

하니스가 이 값을 프로젝트 루트 기준 상대 경로로 해석하고, 루트를 벗어나면
거부한다. 설정하면 플랜 모드가 처음부터 `docs/plans/` 에 쓰므로 **유실이
구조적으로 막힌다.**

> `.gitignore` 가 `.claude/` 를 전부 무시하므로 **이 설정은 커밋되지 않는다.**
> `git config core.hooksPath .githooks` 와 마찬가지로 클론마다 수동이다.
> 빠뜨리면 아래 가드가 하니스 기본 디렉토리에 남은 파일을 잡아 알려준다.

설정해도 **파일명은 여전히 무작위 슬러그**(`giggly-knitting-hollerith.md`)다.
위치만 바뀐다 — 이름과 머리글 정리는 아래 규약대로 사람이 한다.

### 파일명

```
YYYY-MM-DD-작업명.md
```

플랜 모드가 자동 생성한 이름(`giggly-knitting-hollerith.md` 같은 무작위 조합)은
쓰지 않는다. 날짜 접두어로 시간순 정렬이 되고, 작업명으로 내용을 알 수 있게 한다.

### 상태 머리글 (필수)

완료된 계획서를 그냥 두면 **또 하나의 낡은 문서**가 된다. 실제로 이 저장소에서
`docs/db_design.md`·`docs/환경.md`가 그렇게 어긋났다. 파일 맨 위에 반드시 넣는다:

```markdown
<!--
  이 파일은 완료된 계획서다. 현재 상태를 알려면 이 문서가 아니라
  docs/api/*.md (설계) 와 docs/ROADMAP.md (진행) 를 읽어라.
-->

> **상태: 완료** (YYYY-MM-DD)
>
> | | |
> | :--- | :--- |
> | 실행 커밋 | `해시` |
> | 결과물 | 링크 |
> | 계획 이탈 | 있었다면 무엇을 왜 |
> | 계획 오류 | 계획 자체가 틀렸던 부분 |
```

진행 중이면 `**상태: 진행 중**`으로 두고 완료 시 갱신한다.

### 본문은 수정하지 않는다

계획서는 **작성 당시의 기록**이다. 이후 사실이 바뀌어도 본문을 고치지 않는다.
어긋난 점은 상태 머리글의 "계획 이탈"·"계획 오류"에 적는다.

> 이 규칙이 없으면 계획서가 설계서와 중복되는 제3의 진실 원천이 되고,
> 반드시 한쪽이 낡는다.

### 새 계획을 세울 때

1. 플랜 모드로 작성 — `docs/plans/<무작위-슬러그>.md` 에 생성된다
2. 승인·실행 완료 후 **이름을 바꾸고** 상태 머리글을 붙인다 (옮길 필요 없음)
3. 아래 "목록" 표에 한 줄 추가한다

같은 작업을 다시 계획할 때는 **덮어쓰지 말고 새 파일로 만든다** — 덮어쓰면
이전 계획의 결정 근거가 사라진다 (실제로 한 번 잃었다. 맨 아래 주석 참조).

### 잊으면 커밋이 막힌다

규약 의존만으로는 또 잊는다. [`scripts/check-plans.sh`](../../scripts/check-plans.sh)
가 다음을 검사하고, 걸리면 **pre-commit 에서 커밋을 거부**한다.

| 검사 | 잡는 상황 |
| :--- | :--- |
| 이름이 `YYYY-MM-DD-작업명.md` 가 아니다 | 플랜 모드 무작위 이름이 정리되지 않았다 |
| 이름은 맞지만 `상태:` 머리글이 없다 | 이관 절차 2단계를 건너뛰었다 |
| `*.workshop.md` 가 남아 있다 | 플랜 모드 워크샵 중간 파일 |
| 하니스 기본 디렉토리에 `.md` 가 있다 | 이 클론에 `plansDirectory` 가 설정되지 않았다 |

```bash
bash scripts/check-plans.sh          # 위반이 있으면 exit 1
bash scripts/check-plans.sh --warn    # 경고만 (진행 중인 계획이 있을 때)
```

진행 중인 계획은 당연히 이름·머리글이 없으므로 가드에 걸린다. 그 사이의 커밋은
`git commit --no-verify` 로 넘긴다.

> 마지막 검사는 사용자 홈 경로를 보므로 **머신에 종속된다.** CI 에서는 의미가
> 없어 pre-commit 훅에서만 돌린다. 훅 활성화는 클론당 1회:
> `git config core.hooksPath .githooks`
