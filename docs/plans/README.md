# 계획서 보관소

플랜 모드로 세운 계획서를 여기 보관한다. **기록**이지 현재 상태가 아니다.

---

## 왜 저장소 안에 두는가

플랜 모드는 기본적으로 계획서를 `~/.claude/plans/`(저장소 밖)에 만든다. 그
자리에 두면 **새 세션이 존재를 모른다** — 컨텍스트를 비우면 계획이 왜 그렇게
세워졌는지, 무엇을 의도적으로 제외했는지 추적할 수 없다.

커밋 메시지에도 근거가 남지만, 계획서에는 커밋에 없는 것이 있다:

- 각 산출물의 **MUST / MUST NOT** 와 **수락 기준 체크리스트**
- **모델 분할 지침** (설계 판단이 필요한 트랙 A vs 기계적 작업 트랙 B)
- 조사로 확인한 사실과 그 근거 위치
- 범위에서 **의도적으로 제외한** 것

같은 틀로 다음 계획을 세울 때 그대로 재사용한다.

---

## 규약

### 생성 위치 — 설정 + 회수 훅의 2단 구성

손으로 옮기는 규약에만 의존하면 잊는다. 생성 위치 자체를 저장소 안으로
돌리되, **그 설정이 듣지 않는 경우까지 덮는다.**

#### 1단 — `plansDirectory` (커밋된다)

[`.claude/settings.json`](../../.claude/settings.json):

```json
{ "plansDirectory": "docs/plans" }
```

하니스가 이 값을 프로젝트 루트 기준 상대 경로로 해석하고, 루트를 벗어나면
거부한다.

> **`.gitignore` 를 `.claude/` → `.claude/*` + `!.claude/settings.json` 으로
> 바꿔 이 파일은 커밋된다.** 디렉토리째 무시하면 하위 파일을 `!` 로 되살릴 수
> 없어서 규칙을 고쳤다. 개인·머신 종속 설정은 `settings.local.json` 에 두고
> 계속 무시한다. 클론 후 손으로 할 일은 `git config core.hooksPath .githooks`
> 하나만 남는다.

#### 2단 — 회수 훅 (설정이 듣지 않기 때문에 필요하다)

**`plansDirectory` 는 대화형 세션에서 무시된다.** 2026-10-01 실측
(Claude Code 2.1.285):

| 세션 종류 | 계획서 생성 위치 |
| :--- | :--- |
| 비대화형 (`claude -p`) | `docs/plans/` ✅ |
| **대화형 (평소 쓰는 방식)** | **`~/.claude/plans/`** ❌ |

근거: 대화형 세션 2건의 트랜스크립트 `planFilePath` 가 모두 기본 경로였고,
`claude -p --permission-mode plan` 프로브는 `docs/plans/` 에 생성했다.
**폴더 신뢰 여부는 무관하다** — `hasTrustDialogAccepted: true` 인 상태에서도
대화형은 실패했다.

그래서 [`scripts/sweep-plans.sh`](../../scripts/sweep-plans.sh) 를 **`SessionEnd`
훅**으로 걸어, 세션이 끝날 때 기본 디렉토리에 남은 계획서를 `docs/plans/` 로
회수한다. `SessionEnd` 는 `/clear`·resume·종료에서 모두 발화하므로 평소 흐름을
덮는다.

```bash
bash scripts/sweep-plans.sh --dry-run   # 무엇을 옮길지만 본다
bash scripts/sweep-plans.sh             # 회수
```

- 같은 이름이 이미 있으면 **덮어쓰지 않고 건너뛴다**
- 옮긴 파일 이름을 항상 출력한다
- 훅에서 돌므로 어떤 경우에도 세션을 실패시키지 않는다 (`exit 0`)

> **훅으로 생성을 막을 수는 없다.** 파일 생성이 플랜 모드 진입 시점이고 훅
> 이벤트는 그 뒤다. 그래서 "막기"가 아니라 "회수"다.

> **한계:** `~/.claude/plans/` 는 모든 프로젝트가 공유한다. 다른 프로젝트의
> 계획서가 남아 있으면 그것도 이 저장소로 들어온다. 옮긴 이름이 출력되므로
> 섞이면 눈에 띈다.

#### 3단 — 가드 (둘 다 실패했을 때)

세션이 비정상 종료되면 `SessionEnd` 가 발화하지 않을 수 있다. 그때는 아래
`check-plans.sh` 검사 3번이 커밋 시점에 잡는다.

어느 경로로 들어오든 **파일명은 무작위 슬러그**(`giggly-knitting-hollerith.md`)다.
위치만 해결될 뿐 — 이름과 머리글 정리는 아래 규약대로 사람이 한다.

### 파일명

```
YYYY-MM-DD-작업명.md
```

플랜 모드가 자동 생성한 이름(`giggly-knitting-hollerith.md` 같은 무작위 조합)은
쓰지 않는다. 날짜 접두어로 시간순 정렬이 되고, 작업명으로 내용을 알 수 있게 한다.

### 상태 머리글 (필수)

완료된 계획서를 그냥 두면 **또 하나의 낡은 문서**가 된다. 실제로 이 저장소에서
`docs/db_design.md`·`docs/환경.md`가 그렇게 어긋났다. 파일 맨 위에 반드시 넣는다:

```markdown
<!--
  이 파일은 완료된 계획서다. 현재 상태를 알려면 이 문서가 아니라
  docs/api/*.md (설계) 와 docs/ROADMAP.md (진행) 를 읽어라.
-->

> **상태: 완료** (YYYY-MM-DD)
>
> | | |
> | :--- | :--- |
> | 실행 커밋 | `해시` |
> | 결과물 | 링크 |
> | 계획 이탈 | 있었다면 무엇을 왜 |
> | 계획 오류 | 계획 자체가 틀렸던 부분 |
```

진행 중이면 `**상태: 진행 중**`으로 두고 완료 시 갱신한다. 착수 후 중단해 나중에
재개할 계획은 `**상태: 보류**` 로 두고, 본문 끝에 **재개 조건** 절을 덧붙인다
(위 본문은 고치지 않는다).

### 본문은 수정하지 않는다

계획서는 **작성 당시의 기록**이다. 이후 사실이 바뀌어도 본문을 고치지 않는다.
어긋난 점은 상태 머리글의 "계획 이탈"·"계획 오류"에 적는다.

> 이 규칙이 없으면 계획서가 설계서와 중복되는 제3의 진실 원천이 되고,
> 반드시 한쪽이 낡는다.

### 모델 분할 표시 (필수)

**계획을 실행할 때 기계적인 산출물은 하위모델 서브에이전트로 돌린다.** 상위모델
토큰은 설계 판단에 쓰는 자원이고, 이미 확정된 내용을 문서·코드에 옮겨 적는
일까지 상위모델로 하면 비용만 늘고 결과는 같다.

그래서 **계획서는 산출물마다 담당을 표시한다.** 실행 시점에 분류하면 그때그때
기분으로 갈린다 — 계획 단계에서 못박는다.

| 표시 | 뜻 | 기준 |
| :--- | :--- | :--- |
| `[상위]` | 상위모델이 직접 쓴다 | **새로운 판단이 들어간다** — 설계 서술, 트레이드오프, 근거 문장, 도해 |
| `[하위]` | 하위모델에 위임한다 (`model: sonnet`) | **이미 결정된 것을 옮겨 적는다** — 정해진 문구 치환, 표 행 추가, 링크 보강 |

실행 규약:

- **파일 단위로 배타 위임한다.** 두 에이전트가 같은 파일을 동시에 편집하지
  않도록 프롬프트에 "이 파일만 건드려라"를 명시한다
- 치환은 **정확한 old/new 문자열을 프롬프트에 그대로 준다.** "rephrase 금지"를
  박는다 — 하위모델이 설계서 문구를 "개선"하면 안 된다
- **대량 삭제는 위임하지 않는다.** 절·블록 삭제를 맡기면 하위모델이 `sed -i`
  를 쓰고, auto 모드 분류기가 "Irreversible Local Destruction" 으로 거부해
  작업이 멈춘다 (2026-10-01 실측). 삭제는 상위에서 `Edit` 으로 처리한다
- 결과는 **상위모델이 검토한다.** 하위모델 산출물의 책임은 위임한 쪽에 있다

> `상태: 완료` 인 계획서에 이 표시가 없으면 `check-plans.sh` 가 커밋을 막는다
> (검사 4). **2026-10-02 이후 날짜의 계획서에만 적용된다** — 그 전 계획서는
> 이 규약보다 먼저 쓰였고, 위의 "본문은 수정하지 않는다"가 소급 수정을
> 금지하기 때문이다.

### 새 계획을 세울 때

1. 플랜 모드로 작성 — `docs/plans/<무작위-슬러그>.md` 에 생성된다
2. 산출물마다 `[상위]`/`[하위]` 를 붙인다 (위 "모델 분할 표시")
3. 승인·실행 완료 후 **이름을 바꾸고** 상태 머리글을 붙인다 (옮길 필요 없음)
4. 아래 "목록" 표에 한 줄 추가한다

같은 작업을 다시 계획할 때는 **덮어쓰지 말고 새 파일로 만든다** — 덮어쓰면
이전 계획의 결정 근거가 사라진다 (실제로 한 번 잃었다. 맨 아래 주석 참조).

### 잊으면 커밋이 막힌다

규약 의존만으로는 또 잊는다. [`scripts/check-plans.sh`](../../scripts/check-plans.sh)
가 다음을 검사하고, 걸리면 **pre-commit 에서 커밋을 거부**한다.

| 검사 | 잡는 상황 |
| :--- | :--- |
| 이름이 `YYYY-MM-DD-작업명.md` 가 아니다 | 플랜 모드 무작위 이름이 정리되지 않았다 |
| 이름은 맞지만 `상태:` 머리글이 없다 | 이관 절차 2단계를 건너뛰었다 |
| `*.workshop.md` 가 남아 있다 | 플랜 모드 워크샵 중간 파일 |
| 하니스 기본 디렉토리에 `.md` 가 있다 | 이 클론에 `plansDirectory` 가 설정되지 않았다 |

```bash
bash scripts/check-plans.sh          # 위반이 있으면 exit 1
bash scripts/check-plans.sh --warn    # 경고만 (진행 중인 계획이 있을 때)
```

진행 중인 계획은 당연히 이름·머리글이 없으므로 가드에 걸린다. 그 사이의 커밋은
`git commit --no-verify` 로 넘긴다.

> 마지막 검사는 사용자 홈 경로를 보므로 **머신에 종속된다.** CI 에서는 의미가
> 없어 pre-commit 훅에서만 돌린다. 훅 활성화는 클론당 1회:
> `git config core.hooksPath .githooks`
