# 설계서 개정 — 확장성 / 모드별 MMR / 리플레이 폐기 / 미로 밸런스 확정

> 선행 작업: 커밋 `2a56fa9`로 API 설계서 초판(`docs/api/platform.md`,
> `docs/api/games/maze.md`, `docs/ROADMAP.md`)이 완료되었다. 이 계획은 그 **개정**이다.

## Context

초판 설계서에 네 가지 문제가 있다.

1. **하드코딩 범위를 과소평가했다.** `game_sessions`의 2인 컬럼만 지적했으나,
   조사해 보니 **게임 엔진 전반**이 2인 전제다 — `Board.PLAYER1_START`/`PLAYER2_START`,
   `GameState.player1`/`player2`, `current_turn = 2 if current_turn == 1 else 1`,
   `GameStatus.PLAYER1_WIN`/`PLAYER2_WIN`, `Player.player_id not in (1,2)` 예외,
   `MoveValidator`가 단일 `opponent`만 받음, `Pathfinder`의 `player1_pos`/`player1_goal`
   서명. 이 상태로 M3를 시작하면 1:1:1에서 전면 재작업이 난다.
2. **3자 MMR을 쌍별 분해 후 2로 나누는 방식**으로 설계했는데, 2인과 3인은 플레이
   방식이 아예 다르므로 같은 MMR 풀에 둘 이유가 없다. 풀을 분리하면 정규화 자체가
   불필요해진다.
3. **리플레이 4개 엔드포인트를 "판단 필요"로 남겨 두었다.** 명세에 없는 기능이고
   노이즈가 된다. 폐기하되 git에서 복원 가능하게 한 줄만 남긴다.
4. **미로 밸런스 2건이 미결이었다.** 발견한 벽 기억 여부와 벽 설치 거절 피드백.

### 의도한 결과

M3 구현이 N인 확장을 전제로 시작되고, MMR이 게임·모드별로 모듈화되며,
리플레이 잔재가 사라진 상태.

## 산출물

### A-1. `docs/api/platform.md` — MMR을 `(game, mode)`로 분리

**§4.2 수정**

- MMR 키를 `game` 단독에서 **`(game, mode)` 조합**으로 변경
- 모드 예: `maze_1p` × {`duel`, `trio`}, `gomoku_renju` × {`duel`}
- **쌍별 분해 후 2로 나누는 정규화를 삭제한다.** 풀이 분리되면 duel과 변동폭을
  맞출 이유가 없다. 대신 **K 계수를 모드별 파라미터**로 둔다 — 더 모듈화되고
  모드마다 독립 튜닝이 가능하다
- 3자 결과 → Elo 변환은 쌍별 분해를 유지(순위를 쌍 결과로 바꾸는 수단이므로 필요)

**§4.3 / §4.4 수정** — 응답에 `mode` 포함, `GET /leaderboard?game=&mode=` 로 변경.
`mode` 필수.

**§5 수정**

- `user_game_stats` PK를 `(user_id, game)` → **`(user_id, game, mode)`**
- `game_moves` 폐기를 명시, DB `ActionType` 폐기 명시
- **"확장성 원칙" 소절 신설** — 인원 수를 스키마·코드에 박지 않는다.
  `game_participants` + `seat_no`가 그 구현이며, 같은 원칙을 엔진에도 적용한다

**§6 수정** — 리플레이 4개 + `history`를 "판단 필요"에서 **"폐기"로 확정**.
미결 사항 요약에서 해당 항목 제거.

**MUST**
- `(game, mode)` 가 MMR·리더보드·`user_game_stats` 세 곳에서 **일관되게** 쓰인다
- 리플레이 관련 "판단 필요" 표기가 문서에서 **사라진다**

### A-2. `docs/api/games/maze.md` — 밸런스 2건 확정

**§6 수정 — 발견한 벽 누적**

- 상태 패킷에 **`discovered_walls`** 추가. `visible_walls`(현재 시야)와 구분한다
- 플레이어별 발견 집합을 **Redis에 게임 수명 동안 보관** (M3 의존)
- 시야를 벗어나도 유지된다. 한 번 본 벽은 계속 보인다
- 미결 목록에서 이 항목 제거

**§7 전면 수정 — 벽 설치 거절 피드백**

초판은 "에러에 좌표나 경로를 절대 포함하지 않는다"고 썼다. **이 서술을 뒤집는다** —
거절 사실 자체는 **의도된 게임 정보**다. 플레이어는 "여기 놓으면 누군가의 길이
막히는구나"를 알게 되고, 그것을 **스스로 기억해야 한다.**

서버의 의무:

| MUST | MUST NOT |
| :--- | :--- |
| 거절 시 `wall_blocks_path`를 반환한다 | 거절된 좌표 목록을 **누적·저장하지 않는다** |
| "이번 턴에 놓을 수 없음"만 전달한다 | 거절 이력을 조회하는 API를 만들지 않는다 |
| **턴당 거절 시도 횟수를 제한**한다 | 상태 패킷에 "놓을 수 없는 칸" 필드를 넣지 않는다 |
| 한도 초과 시 `probe_limit_exceeded` | 어느 벽이 원인인지, 누구의 경로인지 **알리지 않는다** |

- 턴당 허용 거절 횟수: **3회** (초기값, 플레이 테스트로 조정)
- 카운터는 Redis에 두고 **턴이 바뀌면 리셋**한다
- 제한이 없으면 전 칸을 훑어 벽 그래프를 사실상 복원할 수 있다 — Fog of War가
  무너진다. 제한이 "기억해야 할 정보"라는 설계 의도와도 맞는다

**§11 수정** — 3자 MMR 절을 모드별 분리에 맞게 재작성. `/2` 정규화 삭제,
K를 모드 파라미터로.

**§12 수정** — `error`에 `probe_limit_exceeded` 추가 (신규 타입은 여전히 0개,
기존 `error` 타입의 코드만 추가).

**§13 수정** — `probe_limit_exceeded` 코드 추가.

**미결 목록 수정** — 확정된 2건(발견한 벽, 거절 피드백) 제거. 남는 항목은
FOV 값, 방향 전환 턴 소모, 시간 초과 자동 행동, 3인 배치·벽 개수, `chat` 범위.
"종료 후 전체 맵 공개"는 리플레이 폐기로 **연동 항목이 사라졌으므로 단독 판단**으로
표기 수정.

**MUST**
- `discovered_walls`와 `visible_walls`가 **구분되어** 기술된다
- §7에 MUST NOT 표가 있고 "누적 저장 금지"가 명시된다
- 턴당 제한과 리셋 시점이 명시된다
